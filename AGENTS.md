# Project guidance

Перед анализом или изменением кода прочитай [PROJECT_SPEC.md](PROJECT_SPEC.md) и считай его основным источником требований.

- Это учебный Go-проект для практики интерфейсов, конкурентности, контекста, HTTP и REST API. Не усложняй решение production-архитектурой, если она не помогает этим учебным целям.
- Классы шахтёров образуют закрытый набор ровно из трёх значений: маленький, нормальный и сильный. Клиент выбирает только класс, не передаёт его характеристики; неизвестный класс нужно отклонять. Через API классы нельзя создавать, изменять или удалять.
- Закрытый HTTP-каталог не отменяет расширяемость внутренней модели: предприятие хранит шахтёров через интерфейс `Miner`, определённый в техническом задании.
- `GET /miners/types` возвращает справочник классов и их характеристик.
- Список работающих шахтёров доступен через `GET /miners`; фильтрация по классу выполняется через `GET /miners?type=<class>`.
- Найм шахтёра выполняется через `POST /miners`.
- Общий баланс и состояние предприятия должны быть защищены от гонок; проверка и списание средств при найме или покупке являются единой операцией.
- Не изменяй игровые числа и правила из технического задания без прямого запроса пользователя.
- Если требование не определено, явно обозначь допущение и выбирай простую реализацию, соответствующую учебной цели.
