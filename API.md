# HTTP API

Сервер запускается командой `go run .` на порту 8080. Другой адрес можно задать командой `go run . -addr 127.0.0.1:9000`.

Один процесс обслуживает одну игру. До начала игры доступен каталог классов шахтёров; остальные игровые операции требуют запуска предприятия. Пассивный доход начинается после `POST /enterprise/beginning`. Повторный запуск отклоняется, для новой игры нужно заново запустить процесс.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/miners/types` | Каталог трёх классов с характеристиками и стоимостью |
| POST | `/enterprise/beginning` | Начать игру |
| POST | `/miners` | Нанять шахтёра |
| GET | `/miners` | Работающие шахтёры |
| GET | `/miners?type=small_miner` | Работающие шахтёры выбранного класса |
| GET | `/equipment` | Стоимость оборудования и состояние покупки |
| POST | `/equipment` | Купить оборудование |
| GET | `/enterprise` | Баланс, работающие шахтёры, статистика найма и время |
| POST | `/enterprise/completion` | Проверить победу, вернуть статистику и завершить сервер |

Старый путь `/enterprise/complition` сохранён как синоним завершения игры.

## Найм

`POST /miners`, `Content-Type: application/json`:

```json
{"miner_type":"small_miner"}
```

Допустимые классы: `small_miner`, `normal_miner`, `strong_miner`. Характеристики задаёт сервер; дополнительные поля запроса отклоняются. Ответ `201 Created` содержит `id`, `type`, `cost`, `energy`, `coal`, `interval`, `progression`. `energy` — оставшееся количество добыч, `coal` — объём следующей добычи. `interval` передаётся числом наносекунд: `3000000000` означает три секунды.

## Покупка оборудования

`POST /equipment`, `Content-Type: application/json`:

```json
{"type":"pickaxes"}
```

| Идентификатор | Название | Стоимость |
| --- | --- | ---: |
| `pickaxes` | Кирки | 3000 |
| `ventilation` | Вентиляция | 15000 |
| `carts` | Вагонетки | 50000 |

Каждый вид оборудования можно купить один раз. Успешная покупка возвращает `200 OK` с полями `type`, `cost`, `purchased`.

## Статистика и завершение

`GET /enterprise` возвращает `balance`, `miners`, `hired`, `equipment`, `started_at`, `finished_at`, `duration`, `goal_reached_at`, `goal_duration`, `completed`. Счётчики `hired` учитывают всех нанятых шахтёров, включая закончивших работу. Время `duration` выражено в наносекундах; временные отметки передаются в формате RFC 3339. `goal_reached_at` фиксирует покупку последнего обязательного оборудования, `goal_duration` — время от запуска до этой покупки. Ожидание перед командой завершения увеличивает полную длительность игры, но не время достижения цели.

После покупки всего оборудования отправьте `POST /enterprise/completion`. Сервер остановит добычу, вернёт окончательную статистику с `completed: true` и корректно завершит работу. До покупки всего оборудования запрос отклоняется, игра продолжается. `Ctrl+C` останавливает сервер и все фоновые процессы без засчитывания победы.

Состояние работающих шахтёров учитывается предприятием при получении событий добычи. Это согласованный снимок обработанных событий; он не требует чтения изменяемых полей шахтёра из HTTP-обработчика.

## Ошибки

Ошибки возвращаются как JSON с полем `error`. Неверный JSON, неизвестные поля и неизвестный класс или вид оборудования дают `400 Bad Request`. Игра до запуска, повторный запуск, нехватка угля, повторная покупка и попытка завершить игру без всего оборудования дают `409 Conflict`. Один запрос покупки или найма содержит ровно один JSON-объект.
